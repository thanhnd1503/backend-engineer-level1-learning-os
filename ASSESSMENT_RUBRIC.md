
# Assessment Rubric

## Status definitions

### Pass
The learner can independently implement or explain the competency, meets the acceptance criteria, and can answer follow-up questions without relying on the agent.

### Partial
The learner understands part of the topic but needs notes, hints, or substantial guidance; important edge cases or reasoning are missing.

### Fail
The learner cannot yet explain or implement the topic reliably, or the work contains unresolved critical defects.

### Not assessed
There is not enough evidence to make a judgment.

## Evidence quality

| Evidence | Strength |
|---|---|
| Independent implementation plus relevant tests | Strong |
| Timed independent exercise plus explanation | Strong |
| Debugging write-up with reproduction and root cause | Strong |
| Design note with alternatives and trade-offs | Strong |
| Agent-generated code the learner cannot explain | None |
| Copied tutorial with no modification or explanation | Weak |
| Reading or watching only | None |

## Competency scoring

Score each dimension from 0 to 3:
- 0 — cannot explain or perform;
- 1 — can proceed with substantial guidance;
- 2 — can perform with minor references or hints;
- 3 — independent, correct, and can explain trade-offs.

A competency is Pass only if:
- no critical dimension scores 0 or 1;
- correctness and safety dimensions score 3 where relevant;
- supporting evidence exists;
- the learner passes a short recall or follow-up check.

## Review dimensions

1. Conceptual understanding
2. Implementation correctness
3. Edge-case handling
4. Testing and verification
5. Security and data safety, where relevant
6. Readability and maintainability
7. Ability to explain decisions and trade-offs

## Gate rules

- Critical competencies must be Pass before the final application-readiness review.
- High-priority competencies should be Pass or have a concrete remediation task.
- Medium-priority competencies may be Partial if the learner can explain the fundamentals and the current JD does not make them mandatory.
- Never promote a competency based on calendar completion.

## Oral verification

After an implementation, ask the learner to explain:
1. What problem does this solve?
2. Why did you choose this approach?
3. What alternative did you consider?
4. What can go wrong?
5. How did you verify correctness?
6. What would you improve with more time?

## Final readiness decision

Use one of:
- **Ready to apply** — critical fundamentals demonstrated; CV evidence is honest and aligned.
- **Ready with targeted gaps** — reasonable to apply while remediating clearly bounded gaps.
- **Not ready yet** — one or more critical foundations are not demonstrated; assign a focused remediation plan.

This is a preparation assessment, not a prediction of hiring outcome.
